name: tsp
description: 按 TSP(Team Software Process,团队软件过程)组织开发:分阶段推进、数据驱动的计划与质量跟踪
---

当用户要求以 TSP(Team Software Process)方式开展工作,或希望"有计划、有度量、有复盘"地完成任务时,启用本技能。TSP 的核心理念:**角色分工、分阶段交付、用数据说话(规模/时间/缺陷)、阶段出口评审把关**。

按以下阶段推进,每阶段有明确产出,未满足出口条件不进入下一阶段:

1. **启动(Launch)**:
   - 澄清目标与成功标准:产品目标、质量目标、交付物;列出约束、依赖与风险。
   - 明确分工:谁负责规划 / 设计 / 实现 / 测试 / 质量跟踪。

2. **计划(Plan)**:
   - 把目标拆成可执行任务清单(工作分解 WBS),标注任务间依赖。
   - 估算每个任务的规模与工作量;给每项任务分配负责人。
   - 定义里程碑 / 检查点与"完成定义"(DoD);设定质量目标(如缺陷密度上限,单位:缺陷/千行)。
   - 产出:任务清单 + 规模/工期估算 + 里程碑。

3. **设计(Design)**:
   - 先做整体设计(模块划分、接口、数据流),再做关键模块的详细设计。
   - 设计先经过评审(正确性 / 扩展性 / 风险),通过后再进入实现。

4. **实现(Implement)**:
   - 严格按设计编码;每个模块完成后做代码自审(对照设计,检查边界条件与异常路径)。
   - 记录实现阶段发现的缺陷(位置 / 类型 / 根因),供质量统计使用。

5. **测试(Test)**:
   - 按测试方案编写并运行单元测试与集成验证;补充边界与异常用例。
   - 修复缺陷并回归;汇总缺陷数据(按阶段、按模块、缺陷密度)。

6. **复盘(Postmortem)**:
   - 对比计划 vs 实际:工作量偏差、进度偏差、各阶段缺陷分布。
   - 提炼 2-3 条最值得改进的流程问题,并说明如何落实到后续工作。

交付时按 TSP 风格输出结构化报告:**目标 → 计划(含估算)→ 关键设计决策 → 实现与测试结果 → 质量度量(缺陷统计)→ 复盘与改进项**。

不要跳过阶段或伪造度量数据;所有数据来自实际执行。若只做其中一部分(如只做设计或只做审查),明确说明当前处于哪个阶段。
