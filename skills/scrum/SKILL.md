name: scrum
description: 按 Scrum(敏捷迭代框架)组织开发:以用户故事与冲刺为单位,持续交付可运行增量
---

当用户要求以 Scrum 方式工作,或希望"迭代式、以故事为单位、快速交付可运行成果"地完成任务时,启用本技能。Scrum 围绕三个角色、四个仪式、三个工件:产品待办列表、冲刺待办列表、可运行增量(含完成定义 DoD)。

按以下流程推进:

1. **整理产品待办列表(Product Backlog)**:
   - 把需求写成用户故事:"作为 <角色>,我希望 <功能>,以便 <价值>",每条 1-2 句,附验收标准。
   - 按业务价值与紧急度排序,标注依赖与风险。

2. **冲刺规划(Sprint Planning)**:
   - 从待办列表顶部挑选本冲刺要完成的若干故事,用一句话定义冲刺目标。
   - 把选中故事拆成可执行任务并估算,形成冲刺待办列表(Sprint Backlog)。
   - 明确本冲刺的"完成定义"(DoD):代码完成、有测试、能运行、无遗留关键缺陷。

3. **冲刺执行(每日站会节奏)**:
   - 以站会形式自问:昨天完成了什么 / 今天要做什么 / 有什么阻塞。
   - 遇到阻塞立即解决或上报,不拖到冲刺结束;始终以交付"可运行增量"为目标。

4. **冲刺评审(Sprint Review)**:
   - 演示本冲刺完成的可运行增量,逐条对照故事验收标准;收集反馈。
   - 根据反馈更新待办列表(新增 / 调整优先级)。

5. **冲刺复盘(Sprint Retrospective)**:
   - 检视流程:做得好的(保持)、做不好的(改进)、值得尝试的新做法。
   - 产出 1-3 条可落地的改进项,纳入下一冲刺。

交付时按 Scrum 风格输出:**冲刺目标 → 故事清单(含验收)→ 完成增量说明 → 评审反馈 → 复盘改进项**。

一个冲刺应能交付"可运行、可演示"的成果;不要为了多塞故事牺牲完成质量。若只做其中一部分(如只做待办梳理或只做评审),明确说明当前所处仪式。
